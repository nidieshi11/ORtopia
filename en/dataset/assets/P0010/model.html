P10: The arc-shaped main model M1, where drones and delivery workers work together to achieve efficient delivery.

Source and scope According to pages 1, 3, 4, 5, 6, 7, 8, 9, and 10 of the original paper’s PDF file, the text ranges from (1.1) to (1.26).

Core scope and collection

Retain the arc-based MILP description for M1: It determines which orders to accept in a arrived order batch, through which pick-up and delivery stations, and which delivery staff will relay with the drones and at what times. Each drone can handle at most one order per batch; delivery staff complete the pick-up/delivery arcs in sequence, and cannot carry multiple orders at the same time. The transportation time is fixed, and orders are generated in batches every five minutes. The completion time for each order is determined by the instance.

O,R,D refer to orders, delivery workers, and drones. The optional delivery arc AoP of order o connects from its starting point to the candidate delivery station, while the optional delivery arc AoL connects from the candidate distribution station to the destination. AP = ⋃ ⁡ oAoP ,AL = ⋃ oAoL,A = AP ∪ AL assigns unique numbers to arcs for different orders and types. F = ⋃ ⁡ o(AoP × AoL) represent pairs of orders with same pick and deliver arcs. sr,er represents the virtual starting and ending arcs for delivery workers, and sd represents the virtual starting arc for drones. Delivery workers can use connection sets.

Er = {(a,b) : a ∈ A ∪{sr},b ∈ A ∪{er},a≠b}.

The non-existent connection variable is always set to 0; the connection to (sr,er) allows the delivery person to not serve this batch of orders.

Parameters and variables

vo ≥ 0 represents the revenue from each order, while crC,cdD ≥ 0 represents the cost per unit of driving time. trC,tdD ≥ 0 indicates the known time points at which tasks can be released after completion. LrC,LdD represents the maximum cumulative driving/flying time. This value reflects the remaining battery capacity. The cumulative time is calculated separately for driving and flying scenarios.

wa ≥ 0 represents the driving time for the deliveryman to execute pick-up/send-off arcs a. habC ≥ 0 denotes the travel time from the end point of arc a to the starting point of arc b. hd,aD refers to the flight time for the drone from the current location to the pick-up station at the end point of arc a. habD represents the flight time from the pick-up station to the delivery station. In the original text, point symbols are used in (1.7) and double point symbols in (1.8), but both denote the same flight between stations. This document uniformly refers to this as habD. The virtual arc itself is denoted as wsr = 0. The idle connection driving time is 0, and the time for other terminated connections is defined according to the instance.

la ≥ 0 represents the latest departure time for the delivery driver from point a. If a refers to the delivery arc, then the deadline for delivery is la + wa. The travel time for actual delivery arcs is positive, thus subcircuits that involve negative travel times can be excluded from the calculation.

βa ∈{0,1} Select the delivery arc; γr,abC ∈{0,1} Choose the adjacent connections between delivery agents; γd,abD ∈{0,1} Determine when the drone should fly between different stations. τaC This represents the time at which the delivery agent starts from the starting point of the delivery arc. τaD This indicates the time when the drone departs from the pick-up station. τaD This refers to the time when the drone reaches the delivery station. 𝜀rC,𝜀dD This represents the total travel time.

Set it to H = max ⁡ a∈Ala. Values MraC = trC + hsraC, MabC = la + wa + habC, and MabD = H + habD are acceptable. The time limit for drones is set to 0 ≤ τaD ≤ H, which does not exclude any valid flight that meets the final delivery deadline. This also makes the large constants related to unactivated time intervals valid. When there is no work to be done, the value should be 0.

The time sequence is listed one by one, according to the deliveryman’s r coordinates. This corresponds to the summation of actual arcs in the original text, while avoiding the use of virtual endpoints interchangeably. In the original formula (1.10), the virtual starting point is combined with βa subscripts. This document only applies this formula to actual arcs; virtual starting points are handled separately through departure constraints. The lower limit for drone assignments from the original text is retained. Under non-negative costs, unnecessary drone flights can be eliminated, without generating any additional benefits. la represents the time limit for the deliveryman to reach the order’s starting point. The takeoff time of the drones is determined by the moment when the package is picked up and any connecting constraints that apply.
