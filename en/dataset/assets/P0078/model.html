Instance boundaries

The currently selected model consists of exactly 24 sequential hours. Multiple day objects in the input represent independent 24-period instances, each retaining the initial state rules of this model, with goals and optimality values recorded separately. The optimal values for each day correspond to their respective independent plans. All original hour mappings and missing hour completions are recorded item by item in the repair _ manifest.

Source text correction: 21 corrections for initial closure.

On page 31 of the source PDF, the left side of form (21) contains the startup variable zgi; the right side contains 1 − xg,max ⁡ (1,t−DTg), with no errors in the original text. This historical startup state expression, along with state recursion, limits premature restarts after a shutdown. If the previously extracted file mistakenly changed the left side to w, it will incorrectly prohibit normal shutdowns. Each independent day does not have a default state for the 0th period; the initial state for the starting day is the decision variable xg1,yg1. The initial startup/stop variable is taken as zg1 = wg1 = 0. zg1 = 0 is already implied by the original (20)+(21) and does not participate in any valid constraints or costs. wg1, which does not involve any costs, can be normalized to 0 without loss. Each 24-day period uses the independent initial state of this model and network security constraints. The residual minimum startup/stop time required for day-to-day transitions needs to be determined separately.
